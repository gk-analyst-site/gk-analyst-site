# 📦 Amazon 店舗 売上アップ分析

Amazonのお店の「成績表」を読んで、**どの商品を・どう直せば売上が上がるか**を自動で判定するしくみです。

---

## 🧩 しくみ（小学生向け）

売上は、かけ算でできています。

```
売上 ＝ 見に来た人（セッション） × 買う率（CVR） × 1個のねだん
```

どれか1つが弱いと、売上は伸びません。このプログラムは商品ごとに
「どこが弱いか」を見つけて、5つのグループに分けます。

| グループ | どういう状態？ | やること |
|---|---|---|
| 🔴 カートを取られている | お客さんは来ているのに、他のお店から買われている | 値段・在庫・発送日数を見直す |
| 🔴 見られているのに買われない | お店の前は人がいっぱい、でも買わずに帰る | 画像・タイトル・レビュー・値段を直す |
| 🟡 買われやすいのに人が来ない | 来た人はよく買うのに、来る人が少ない | 広告・キーワードで人を呼ぶ |
| 🟢 勝ち商品 | 人も来て、よく売れている | 在庫を切らさない・もっと伸ばす |
| ⚪ ほとんど動いていない | 人も来ないし売れない | 見直す、ダメなら売り切って止める |

🔴 から先にやると、いちばん早く売上が上がります。

## ▶️ 手動での使い方（CSVを自分で置く場合）

### 1. 成績表CSVをダウンロード
1. セラーセントラルにログイン
2. 上のメニュー「レポート」→「ビジネスレポート」
3. 左の「商品別」→「**詳細ページ 売上・トラフィック（子商品別）**」
4. 期間を「過去7日間」などにして、右上の「ダウンロード(.csv)」

### 2. ファイルを置く
`amazon-shop/data/` に、日付の名前で置きます。

```
amazon-shop/data/2026-10-10.csv
```

毎週同じ曜日に置くと、**前回と比べて増えた・減った**も出ます。

### 3. 分析する
```bash
python3 amazon-shop/analyze.py
```

できあがるもの（`amazon-shop/output/`）：
- `report.html` … スマホで見られる診断レポート
- `todo.md` … 今週やることのチェックリスト
- `summary.json` … 数字のまとめ（あとで別の道具で使う用）

> CSVが置かれていないときは `sample/` のお試しデータで動きます。

## 🔒 大事：売上データを守るために

**このリポジトリは「公開」**（誰でも見られる）です。
そのため、
- `data/*.csv` と `output/` は **GitHubに上がらない設定**（`.gitignore`）にしてあります。
- 自動ワークフロー（`.github/workflows/amazon-shop-report.yml`）は
  **非公開リポジトリのときだけ**動くようにしてあります。

### 自動化をしたいとき（下の「全自動にする」も参照）
1. GitHubで**非公開（Private）の新しいリポジトリ**を作る
2. `amazon-shop/` フォルダと `.github/workflows/amazon-shop-report.yml` をコピー
3. `.gitignore` から `amazon-shop/data/*.csv` の行を消す（非公開なら置いてOK）
4. スマホのGitHubアプリから `data/` にCSVをアップロード → 自動でレポートが更新

---

## ⚙️ 判定のきびしさを変えたいとき

`analyze.py` の上のほうの数字を変えます。

| 名前 | 今の値 | 意味 |
|---|---|---|
| `BUYBOX_OK` | 90 | カート獲得率がこれ未満なら🔴 |
| `CVR_LOW_RATIO` | 0.6 | 買う率がお店平均の0.6倍未満なら「買われない」 |
| `CVR_HIGH_RATIO` | 1.3 | 買う率がお店平均の1.3倍以上なら「買われやすい」 |
| `TRAFFIC_TOP` | 0.7 | セッション数が上位30%なら「人がよく来ている」 |

## 🤖 全自動にする（CSVダウンロードも不要）

Amazonの公式の窓口「SP-API」から、毎朝6:30に成績表を自動でもらって分析します。
プログラムは `fetch_spapi.py` です。

```
① Amazon(SP-API) ──成績表──► ② fetch_spapi.py ──CSV──► ③ analyze.py ──► レポート
   (公式の窓口)                (毎朝もらってくる係)        (診断する係)
```

### 取れるデータは2種類（自動で切り替わります）
| お店の状態 | 取れるもの | 診断 |
|---|---|---|
| ブランド登録あり | 売上・個数・**セッション・カート獲得率** | 5グループのフル診断 |
| ブランド登録なし | 売上・個数（注文データ） | 「売上が落ちている／伸びている」など前回比の診断 |

### 準備（最初の1回だけ・30分くらい）

**ステップ1：開発者登録をする**
1. セラーセントラルにログイン（**主アカウント＝お店を作った人のアカウント**で）
2. 右上メニュー「アプリとサービス」→「アプリを開発」
3. 「開発者プロファイル」を入力
   - 用途は「自分のお店だけで使う（プライベート開発者）」を選ぶ
   - 使う権限（ロール）にチェック：
     - **ブランド分析**（ブランド登録をしている場合）
     - **在庫と注文の追跡**
     - **商品の出品**（商品名をもらうため）
4. 審査を待つ（数日かかることがあります）

**ステップ2：アプリを作って鍵を3つもらう**
1. 「アプリを開発」画面 →「アプリクライアントを追加」
2. 名前は何でもOK（例：`shop-report`）、API種類は「SP-API」
3. できたアプリの「LWA認証情報」→「表示」で次の2つをメモ
   - **クライアントID**（`amzn1.application-oa2-client.` で始まる）
   - **クライアントシークレット**
4. アプリの右の「▼」→「**アプリを承認**」→ **リフレッシュトークン**（`Atzr|` で始まる）をメモ

> ⚠️ この3つは「お店の合いかぎ」です。チャットやメールに貼らず、次のSecretsにだけ入れてください。

**ステップ3：非公開リポジトリを用意する**
売上が丸見えにならないよう、自動化は**非公開（Private）リポジトリだけ**で動きます。
1. GitHubで新しい **Private** リポジトリを作る
2. `amazon-shop/` フォルダと `.github/workflows/amazon-shop-report.yml` をコピー

**ステップ4：鍵をSecretsに入れる**
1. 非公開リポジトリ →「Settings」→「Secrets and variables」→「Actions」
2. 「New repository secret」で3つ登録

| 名前 | 中身 |
|---|---|
| `SPAPI_CLIENT_ID` | クライアントID |
| `SPAPI_CLIENT_SECRET` | クライアントシークレット |
| `SPAPI_REFRESH_TOKEN` | リフレッシュトークン |

**ステップ5：動かしてみる**
1. 「Actions」タブ →「Amazon店舗レポートを作る」→「Run workflow」
2. 5〜10分で `amazon-shop/output/report.html` ができます
3. あとは毎朝6:30に自動で更新されます

### 期間のしくみ
- 毎朝「**2日前までの7日間**」の成績をもらいます（Amazon側の反映に2日ほどかかるため）
- 比べる相手は「**ちょうど1週間前の成績表**」です（毎日同じ期間がずれるので、曜日のクセが消えます）

### うまくいかないとき
| 表示 | 原因と直し方 |
|---|---|
| `鍵が足りません` | Secretsの名前のつづりを確認 |
| `HTTP 400` / `invalid_grant` | リフレッシュトークンが違う → アプリを承認し直して新しいものを登録 |
| `HTTP 403`（売上・トラフィック） | ブランド分析の権限がない → 自動で注文データに切り替わるので問題なし |
| `HTTP 403`（注文レポート） | 「在庫と注文の追跡」権限を開発者プロファイルで追加 |
